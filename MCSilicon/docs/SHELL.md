# MCS 가상 쉘

마인크래프트 안에서 `/lx`로 접속하는 "리눅스 흉내" 쉘. **진짜 리눅스 에뮬레이션이나
실행이 아니다** - 정해진 명령어 몇 개만 아는, 그 명령어 이름과 UX만 리눅스를 흉내낸
자체 구현이다.

## 접속

콘솔/채팅에 `/lx`를 치면 접속된다. 접속 위치는 항상 `/`. 프롬프트는

```
username:path%
```

접속해 있는 동안 보내는 일반 채팅 메시지는 전부 쉘 명령으로 해석되고(다른
플레이어에게는 채팅으로 안 보임), `exit`으로 나간다.

## 저장 위치

월드 세이브가 아니라 **마인크래프트 실행 디렉토리** 기준이다(Forge의
`FMLPaths.GAMEDIR` - 기본 설치라면 Windows에서 `%APPDATA%/.minecraft`, 서버라면
서버 실행 폴더). 그래서 월드를 나갔다 들어오거나 다른 월드에 들어가도 작업물이
남는다.

```
<게임 디렉토리>/mcs/root/home/<username>/...      각 유저의 홈(서로 다른 루트, 서로 접근 불가)
<게임 디렉토리>/mcs/root/.mounts.properties        마운트 테이블
<게임 디렉토리>/mcs/root/.accmnt.properties        마운트 허용 목록
```

## 지원 명령어

`ls`, `cd`, `cat`, `mkdir`, `rmdir`, `rm [-r]`, `cp [-r] <원본> <대상>`,
`mv <원본> <대상>`, `clear`(진짜 화면을 못 지우니 빈 줄을 40개 보내 흉내만 냄),
`exit`.

## 의도적으로 지원하지 않는 것

- `sudo` 등 권한 상승 프로그램
- `xserver` 등 불필요한 프로그램
- 쉘 문법: 리다이렉션(`>` `>>` `<`), 파이프(`|`), 글롭(`[` `]`) - 이 기호가
  섞인 줄은 바로 거부 메시지가 뜬다. 인자 파싱도 공백으로만 나누고 따옴표
  처리는 없다(`"이름 있는 파일"` 같은 건 아직 불가 - 알려진 제약).

## mcc - Minecraft Chip Compiler

```
mcc chipname            % mcs:username:chipname 으로 등록됨
mcc chipname -o wantname  % mcs:username:wantname 으로 등록됨
```

`chipname`(확장자 없으면 `chipname.mcsl`도 시도) 파일을 MCSL로 컴파일해서,
성공하면 그 결과를 **물리 블록 없이** `ChipRegistry`에 등록한다. 등록된 이후엔
다른 칩에서 바로 `USE CHIP mcs:username:chipname;`처럼 참조해서 쓸 수 있다
("사용 가능한 칩이 된다" = USE로 쓸 수 있게 된다는 뜻으로 구현했다).

칩 DSL(MCSL)도 이에 맞춰 `USE CHIP` 뒤에 `:`나 `/`로 구분된 경로를 쓸 수
있도록 확장했다:

```
USE CHIP mcs:alice:HA;      // 콜론 경로
USE CHIP path/to/mychip;    // 슬래시 경로
USE CHIP HA;                 // 구분자 없는 기존 방식도 그대로 동작
```

경로의 **마지막 조각**이 그 칩 안에서 `<<`로 부를 때 쓰는 짧은 이름(alias)이
된다(`mcs:alice:HA` -> `HA`, `path/to/mychip` -> `mychip`). 실제 `ChipRegistry`
조회는 항상 전체 경로 문자열로 이루어진다. (제약: 경로 조각에 `CHIP`처럼 MCSL
예약어와 겹치는 이름은 쓸 수 없다 - 예를 들어 `path/to/chip`은 안 되고
`path/to/mychip`은 된다.)

물리적으로 배치된 칩 블록은 지금처럼 구분자 없는 짧은 이름으로 등록되므로,
mcc가 쓰는 `mcs:` 이름공간과 절대 겹치지 않는다(짧은 이름은 애초에 `:`를
포함할 수 없다).

## 다중 사용자 격리 / mount

유저마다 완전히 분리된 루트(`/`)를 갖고 서로 접근 불가능한 게 기본이다.
다른 유저의 디렉토리를 보려면 명시적으로 마운트해야 한다.

```
%mount anotherusername /wantdir
```

- `/wantdir`은 **내 쪽**에서 존재하지 않거나 비어있어야 한다.
- OP(진짜 바닐라 서버 오퍼레이터 권한)면 허락 없이 바로 가능.
- OP가 아니면 상대방이 먼저 자기 쉘에서 허락해야 한다:

```
%accmnt username     % username이 나를 마운트하는 걸 허용
%denmnt username      % 허용 취소
```

`%denmnt`로 허용을 취소해도 이미 마운트되어 있던 자리 자체는 사라지지 않는다
- 그 시점 내용이 owner(마운트를 건 사람) 쪽에 **독립된 사본**으로 고정되고,
그 뒤로는 양쪽에 변경사항이 동기화되지 않는다(요청 그대로 구현).

## 안전 관련

- 사용자가 입력한 경로는 절대 실제 파일 경로로 바로 안 넘어간다. 먼저 가상
  경로 공간 안에서 `.`/`..`를 계산해 정규화하고(루트 `/` 위로는 못 올라감),
  그 다음에야 실제 디스크 경로로 매핑한 뒤, 그 결과가 의도한 홈 디렉토리
  바깥으로 새지 않는지 한 번 더 확인한다(경로 순회 방지).
- 물리 디스크 저장 위치는 마인크래프트 자신의 게임 디렉토리 안(`mcs/` 하위)
  으로만 한정했다 - 호스트 컴퓨터의 임의 경로(예: 실제 `C:\`나 `/` 루트)에는
  쓰지 않는다.
- 앞서 별도로 요청됐던 "칩 DSL 안에 자바 코드를 그대로 심어 실행하는 기능"은
  구현하지 않았다 - 블랙리스트 방식으로는 안전하게 막을 수 없어서다(자세한
  이유는 대화 기록 참고). 대신 안전한 화이트리스트 방식인 `GROUP` 문법으로
  대체했다.

## 아직 안 된 것 (다음 단계)

- `vi`: 아직 없음. 다음 단계에서 만들 것.
- 마우스 클릭/드래그 상호작용(= `vi`용 GUI): `vi`와 함께 나중에.
- 인자 파싱에 따옴표 없음(공백 포함 파일명 불가).
- 이 코드는 실제 Forge 1.21.1 jar에 대해 컴파일 검증을 아직 못 했다(이 세션의
  샌드박스에 Forge 의존성을 받아올 네트워크 접근이 없음) - DSL 쪽 코드처럼
  독립적으로 javac 검증하지 못했고, 실제 프로젝트 빌드 시 API 이름/시그니처가
  약간 다를 수 있는 부분(`ServerChatEvent`의 메시지 조회 메서드,
  `Player#hasPermissions` 등)이 있을 수 있어 확인이 필요하다.
